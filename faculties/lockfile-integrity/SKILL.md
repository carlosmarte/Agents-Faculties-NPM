# Lockfile integrity

## Why

The lockfile, not `package.json`, decides exactly which tarballs get installed. A lockfile
entry can be altered to point at an attacker's server or a git repository while
`package.json` looks unchanged, and such a diff is rarely read in review.

## Rules

- `package-lock.json` is committed and never gitignored.
- Only npm writes it. Never edit it by hand; change `package.json` or run an npm command.
- Never use `--no-package-lock` or set `package-lock=false`.
- Automated environments install with `npm ci`, never `npm install`. `npm ci` installs
  exactly what the lockfile says and fails if it disagrees with `package.json`.
- Every locked dependency resolves over HTTPS from an expected registry and has an
  `integrity` hash. No git, plain-HTTP or arbitrary-URL dependencies.

Current npm can enforce the last rule itself. Where `npm config get allow-git` does not
print `undefined`, add to the project `.npmrc`:

```ini
allow-git=none
allow-remote=none
```

## Procedure

1. **Check** from the project root (or pass `--dir <project>`):

   ```sh
   <skill-dir>/scripts/lockfile-check.sh
   ```

   Exit code 1 lists each offending entry. Allowed hosts are the registries named in the
   project `.npmrc` (`registry.npmjs.org` if there are none), plus any in the
   `LOCKFILE_ALLOWED_HOSTS` environment variable (comma-separated).

2. **Fix findings** at the source: replace the git/URL dependency in `package.json` with a
   registry release, or configure the correct registry in `.npmrc`, then run `npm install`
   to regenerate the lockfile. Do not patch the `resolved` field.

3. **Reviewing a lockfile diff:** run the check on the branch, and confirm that every
   package that changed is explained by a `package.json` change in the same diff.

4. **CI and Dockerfiles:** use `npm ci`, and run the check before it.

## Hook

`hooks/lockfile-integrity.sh` enforces this. Registered on PreToolUse it blocks hand-edits of
the lockfile and commands that disable it; registered on PostToolUse it runs the check after
any npm command that changes dependencies.
